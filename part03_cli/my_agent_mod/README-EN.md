# my_agent_mod — ADK CLI Custom Weather Agent

This agent populates the standard scaffold generated by `adk create my_agent_mod` with the **"First Agent" example from Lecture Slide 50**. It includes a custom tool (`get_weather`) and root `.env`-based authentication switching (Google AI Studio API Key vs. Vertex AI). When asked about the weather in a specific city, the model calls the tool function (Function Calling) to answer in a single sentence, while answering other general questions using its own knowledge.

---

## 1. Directory Structure

```text
my_agent_mod/
├── agent.py          # 📄 [Core Code] Loads root .env, implements get_weather tool and weather_agent (root_agent)
├── __init__.py       # 📄 [Package Init] Module export for ADK loader (`from . import agent`)
├── README-KR.md      # 📄 [Documentation] Korean guide
├── README-KR.pdf     # 📄 [Documentation] Korean guide (PDF)
├── README-EN.md      # 📄 [Documentation] English guide (this file)
├── README-EN.pdf     # 📄 [Documentation] English guide (PDF)
└── .adk/             # ⚡ [Runtime Generated] Data folder automatically created by ADK during local execution
    └── session.db    # ⚡ [Dynamically Generated] Local SQLite database storing conversation sessions
```

> **Note (`.env` Location)**: Instead of keeping a separate `.env` file inside this folder, `agent.py` directly loads the workspace root `.env` file (`ADK_Labs/.env`) via `Path(__file__).resolve().parents[2] / ".env"`.

### Key Files and Roles
- **`agent.py`**:
  1. Loads the root `.env` file and cleans up environment variables based on `GOOGLE_GENAI_USE_VERTEXAI` to prevent conflicts between **Vertex AI mode** (defaults `GOOGLE_CLOUD_LOCATION` to `"global"` and removes API key variables) and **Google AI Studio API Key mode** (removes GCP project/location variables).
  2. Defines the weather lookup tool `get_weather(city: str) -> dict`.
  3. Defines `root_agent` (`name="weather_agent"`) configured with `tools=[get_weather]` and model `os.getenv("ADK_MODEL", "gemini-flash-latest")`.
- **`__init__.py`**: Exposes the agent module via `from . import agent` so the ADK loader can discover it.
- **`.adk/session.db`**: Local SQLite database automatically created to persist session history across CLI and web runs.

## 2. Operation Structure (`agent.py`)

- **Entry Point**: `root_agent` in `agent.py` (`name="weather_agent"`)
- **Model**: `os.getenv("ADK_MODEL", "gemini-flash-latest")`
- **Role (`description` & `instruction`)**:
  - `description`: `"일반 질문 답변 및 도시 날씨를 알려주는 에이전트"` (Agent that answers general questions and provides city weather)
  - `instruction`: `"사용자가 묻는 도시의 날씨를 get_weather로 조회해 한 문장으로 답하고, 그밖의 질문은 아느대로 답해줘."` (Look up the weather of the city asked by the user with `get_weather` and answer in one sentence; answer other questions to the best of your knowledge.)
- **Tool (`get_weather`)**:
  ```python
  def get_weather(city: str) -> dict:
      """Returns current weather for a specified city."""
      data = {"서울": "맑음, 18°C", "부산": "흐림, 20°C"}
      if city in data:
          return {"status": "success", "report": data[city]}
      return {"status": "error", "error_message": f"{city} 정보 없음"}
  ```

## 3. How to Run

Run `my_agent_mod` from the parent directory (`part03_cli`) using ADK CLI commands:

```bash
# 1. Navigate to parent directory (skip if already in part03_cli)
cd part03_cli

# 2. Run terminal interactive REPL
adk run my_agent_mod

# 3. Run with in-memory session (no session.db created/used)
adk run --in_memory my_agent_mod

# 4. Run and save session to a file (creates my_agent_mod/s1.session.json upon exit)
adk run --save_session --session_id s1 my_agent_mod

# 5. Resume from a saved session file
adk run --resume my_agent_mod/s1.session.json my_agent_mod

# 6. Launch web UI (open http://localhost:8000 in your browser and select my_agent_mod)
adk web --port 8000

# 7. Launch headless REST / SSE API server
adk api_server --port 8000
```
